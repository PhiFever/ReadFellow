# 索引与检索

每本书对应一个 `library/<collection>.db`。SQLite 表结构和生产用的 `SqliteChunkStore` 在 `library.py`。

## 建库与续跑

`chunk_document` 按文本单元切块，记录行号、字节偏移和原文。chunk id 由源文件 SHA-256 的前 12 位和从 0 开始的六位序号组成。章节与切块共用 `iter_headings` 识别标题。章节正文包含标题、原有换行和空行，直到下一标题前一行。每个 chunk 按起始行关联章节，首个标题之前的 chunk 保留，所属章节为空。

`index` 用固定的短文本探测模型的向量维度，随后在一个事务中写入书目和全书章节。书目记录源路径、源文件哈希、切块器版本、切块参数、embedding 模型和维度。这些值必须与已有书目逐项相同才能续跑。任一项改变，需加 `--rebuild`。重建在同一事务中替换四张索引表并写入书目和章节，保留读者状态和逐章笔记。库的 schema 版本由 `PRAGMA user_version` 记录。

每批只为新增或文本哈希有变化的 chunk 计算向量。chunk 原文、向量和对应的 FTS5 行一起提交。中断后，`status` 会显示已提交数与应有数，例如 `8/16 docs`。重跑原命令即可补齐。`--limit` 只限制本次索引的 chunk 数；去掉它重跑可以继续索引后面的内容。

## 查询与证据

八个读取命令统一经过 `app._read_collection`。它与 `status`、进度管理共用 `_open_book` 校验书目。源文件在场时核对哈希，源文件缺失时使用库里保存的章节和原文。哈希或切块器版本不符会阻止读取；`status` 报告原因和实际行数。检索结果携带原文、chunk id、源路径和行范围。CLI 展示前 260 个字符，`fetch` 可按 id 取全文。

- 向量通道先用 SQL 限定进度，再用 NumPy 对小端 float32 向量求内积。Ollama 向量已做 L2 归一化。内积相同的 chunk 按序号升序排列。
- 关键词通道对原文和查询都用 jieba 精确分词，去掉纯空白和标点。查询词分别加引号，用 OR 连接。FTS5 在同一条 SQL 里过滤进度并按 BM25 排序。
- `hybrid` 按两条通道内的排名做 RRF 融合，返回各通道候选数及命中的排名。

## 进度

`--max-chapter V:N` 由库中的章节表换算出结束行。书内章号重回 1 时开启下一卷；章号撞号时列出候选与对应的 `--max-line`。章号、行号和 chunk 序号上限可以组合，取交集。读取命令默认使用库内保存的进度。首次读取前用 `progress set V:N`、`progress set --line N` 或 `progress set --all` 设置，之后用 `progress show` 查看。单次章号或行号上限只能收紧范围。源文件变化并重建后，需要重新设置进度。在旧库上执行 `progress set` 会在同一写事务中补齐读者状态表和笔记表，并升级到 v3。

`SqliteChunkStore` 的检索方法接收 `ProgressFilter`，过滤条件是 chunk 结束行和序号都不超过各自上限。`fetch_chunk` 先按 id 取原文，再用 `allows()` 区分找不到和超出进度。越界时只返回状态。

## 目录、原文与精确查找

`toc [--chapters A-B]` 按目录序号列出可读章节，部分可读的章节只统计可见行的非空白字符。`read --chapters A-B` 按目录序号取连续原文，`read --lines A-B` 按源行号取文。首个标题前的行不在章节表里。`read` 保留空行，输出上限为 60000 个字符。

`find 词` 按字面查找，区分大小写。每行只计一次命中。每章统计涵盖全部可读命中，`--limit` 只限制展示的命中行数。这三个命令都支持 `--json`，也都能在源文件缺失时直接读取书库。

`toc` 和 `find` 只为整章可读的章节展示摘要。它们按最近一次启用的摘要配置和当前章节哈希批量读取笔记，跳过标有剧透的摘要。`toc` 还会列出对应的情节标签。

`notes --chapters A-B [--json]` 按目录序号读取最近一次启用的 moments 配置。已存进度和单次上限共同决定可读范围。只列出整章可读的章节，跳过尚未扫描的笔记和已隐藏的关键时刻。章内没有可见笔记时，文本输出保留章头并显示 `no notes`。每条引文附源路径，源文件行号由章首行加上章内行号再减一得到。与 `read` 一样，按文本格式计入 60000 字符预算；下一条放不下时保留已输出的完整条目，JSON 返回 `truncated=true`。
